# 03 — Tools & asset pipeline

A large part of this game's content is **generated by GDScript tools** rather than built by hand
in the editor. The tools live in `tools/` and are developer-only. The game never runs them.

| Tool | Kind | Produces |
|---|---|---|
| `tools/build_resources.gd` | `SceneTree` script (`--script`) | `resources/frames/*.tres` (8 SpriteFrames) and `resources/city_tileset.tres` |
| `tools/build_level.gd` + `build_level.tscn` | Scene with a `Node` script | `scenes/level/level_1.tscn` |
| `tools/playtest.gd` + `playtest.tscn` | Scene with a `Node` script | A console report and the screenshots in `tools/screenshots/` |
| `tools/snap.gd` + `snap.tscn` | Scene with a `Node` script | One screenshot of any scene |

## Why generate content with code?

* **Volume.** Six characters × up to nine animations × 3–9 frames is about 300 frames. Slicing them
  by hand in the SpriteFrames editor is slow and error-prone.
* **Repeatability.** Change a number (an FPS value, a platform position) and rebuild in a second.
* **Documentation.** The level layout is readable data (`PITS`, `PLATFORMS`, `ENEMIES`…)
  instead of hundreds of node positions.

The output is ordinary Godot resources and scenes, so you can still open and edit them in the
editor afterwards.

## The pipeline, in order

```
asset/*.png  ──(Godot import)──►  .godot/imported/*
     │
     ▼
tools/build_resources.gd  ──►  resources/frames/player.tres, mook_gunner.tres, …
                          ──►  resources/city_tileset.tres
     │
     ▼
tools/build_level.gd      ──►  scenes/level/level_1.tscn  (uses the tileset + all scenes)
```

### Step 0 — Import the PNGs

```bash
godot --headless --import
```

Godot has to **import** every PNG (convert it to an engine texture, written into `.godot/`) before
scripts can `load()` it. The editor does this automatically when it opens. `--import` does it
without opening a window.

### Step 1 — Build sprite animations and the tileset

```bash
godot --headless --script res://tools/build_resources.gd
```

`build_resources.gd` uses `extends SceneTree`. A script started with `--script` *becomes the main
loop*, so its work happens in `_init()` and it ends with `quit()`. It needs no scene. Autoloads are
**not** loaded in this mode, which is fine because this script does not use `Game`.

What it does:

1. **`build_character(id, folder)`**: for every 32 px-tall PNG in a character folder, makes one
   animation. The name comes from the file name: `Walk+Shot.png` → `walk_shot`. The frame count is
   `width / 32`. FPS and looping come from the `FPS` and `LOOPING` tables at the top of the file.
2. **`build_single(id, path, frame_w, fps, loop)`**: one animation called `default` (grenade:
   32 px frames; explosion: 64 px frames).
3. **`build_tileset()`**: a 16 × 16 `TileSet` over `asset/Tiled/Tile1.png` with two physics
   layers: solid ground (collision layer 1) and one-way platforms (collision layer 5).

| Output file | Source |
|---|---|
| `resources/frames/player.tres` | `asset/Characters/Character_1` |
| `resources/frames/mook_gunner.tres` | `asset/Enimies/Enimies_1` |
| `resources/frames/mook_brute.tres` | `asset/Enimies/Enimies_4` |
| `resources/frames/boss_rook.tres` | `asset/Enimies/Enimies_3` |
| `resources/frames/boss_bonecrusher.tres` | `asset/Enimies/Enimies_5` |
| `resources/frames/boss_plague_doctor.tres` | `asset/Enimies/Enimies_2` |
| `resources/frames/grenade.tres` | `asset/Characters/Other/Granate_Cast.png` |
| `resources/frames/explosion.tres` | `asset/Characters/Other/Granate_Explosion.png` |
| `resources/city_tileset.tres` | `asset/Tiled/Tile1.png` |

### Step 2 — Build the level

```bash
godot --headless res://tools/build_level.tscn
```

This one runs as a **scene** (not `--script`) because it instantiates the player, enemies and
HUD, and their scripts reference the `Game` autoload. Autoloads only exist when the game starts
normally.

It creates a `Node2D` tree in memory and saves it as a scene file:

```gdscript
var packed := PackedScene.new()
var err := packed.pack(level_root)
if err == OK:
    err = ResourceSaver.save(packed, OUT)
```

> **Important:** `PackedScene.pack()` only saves nodes whose `owner` is the root. That is why
> every node is added through the helper `_add()`, which sets `node.owner = level_root`.

All layout data sits at the top of `build_level.gd`, in **tile units** (1 tile = 16 px) unless
marked `_px`:

| Constant | Format | Meaning |
|---|---|---|
| `PITS` | `[first_tile, last_tile_exclusive]` | Gaps in the ground |
| `PLATFORMS` | `[first_tile, row, length]` | One-way ledges |
| `ARENAS` | `[left_tile, boss_scene_path, reward]` | Boss arenas |
| `ENEMIES` | `[type, x_px, y_px]` | `"gunner"` or `"brute"` spawn points |
| `PICKUPS` | `[kind, x_px, y_px]` | Free pickups along the street |

Decoration (buildings, posters, street junk) is random but **seeded** (`rng.seed = 2026`), so
every rebuild gives the same street.

> ⚠️ **Re-running `build_level` overwrites `level_1.tscn`.** If you have painted tiles or moved
> enemies by hand in the editor, those changes are lost. Pick one workflow per change: edit the
> data and rebuild, or edit the scene by hand.

### Re-running the whole pipeline

```bash
cd path/to/dark-city
godot --headless --import
godot --headless --script res://tools/build_resources.gd
godot --headless res://tools/build_level.tscn
```

## `snap.gd`: one screenshot of any scene

```bash
godot res://tools/snap.tscn -- res://scenes/ui/title.tscn 00_title
```

Everything after `--` is a **user argument**, read with `OS.get_cmdline_user_args()`. The tool
loads the scene, waits 1 second, waits for the frame to finish drawing
(`RenderingServer.frame_post_draw`), then saves `tools/screenshots/00_title.png`. It needs a real
window, because a headless run draws nothing.

## The `.gdignore` files

`asset/__MACOSX/.gdignore` and `tools/screenshots/.gdignore` are empty files that tell Godot to
**skip a folder**. `__MACOSX` holds macOS metadata files named like `._Idle.png` that are not real
images and would produce import errors. Screenshots don't need importing because nothing in the
game loads them.

## Useful command-line flags

| Flag | Effect |
|---|---|
| `--path <dir>` | Run the project in `<dir>` (otherwise uses the current folder) |
| `-e` / `--editor` | Open the editor |
| `--headless` | No window, no rendering (fast; good for tools and CI) |
| `--script <file>` | Run a `SceneTree`/`MainLoop` script instead of the main scene |
| `--import` | Import resources, then quit |
| `--fixed-fps 60` | Pretend every frame takes exactly 1/60 s (deterministic playtests) |
| `<scene.tscn>` | Run that scene instead of the main scene |
| `-- a b c` | User arguments, available via `OS.get_cmdline_user_args()` |
