**Why `scenes/` and `scripts/` are separate folders:** it is a matter of taste. Many Godot projects
keep `player.tscn` and `player.gd` side by side. Here, mirrored folders make it easy to see "all
the code" or "all the scenes" at once. The two layouts work equally well.

## Runtime flow

```
 Godot starts
     │  creates autoloads  Settings → Audio → SaveGame → Game
     ▼
 intro.tscn   (skippable; skipped entirely if "Play intro at start" is off)
     ▼
 title.tscn ── CUSTOMIZE / SETTINGS / CREDITS open on top of the title
     │
     ├──(NEW GAME)──► Game.start_game()     resets score/time
     ├──(CONTINUE)──► Game.continue_game()  reads savegame.json → SaveGame.pending
     ▼
 level_1.tscn
     │  level.gd: camera limits, weather, street music,
     │            SaveGame.apply_pending()  or  the "STAGE 1" card
     │  player walks right… street 1
     │  BossArena1 trigger → DEADEYE ROOK   ─┐ (autosave after
     │  street 2 → BossArena2 → BONECRUSHER ─┘  each of these)
     │  street 3 → BossArena3 → THE PLAGUE DOCTOR (is_final)
     │
     │  pause menu: RESUME · SAVE GAME · LOAD GAME · SETTINGS · RESTART · QUIT TO TITLE
     ▼
 ┌───────────┴─────────────────────┐
 player_died                   boss_defeated(is_final = true)
     ▼                               ▼
 "YOU DIED"                     "CITY SAVED"
 [RETRY] [LOAD LAST SAVE] [TITLE]   [PLAY AGAIN] [TITLE]

 RETRY, PLAY AGAIN  → Game.restart_level() → start_game() → level_1.tscn
 LOAD LAST SAVE     → Game.continue_game()
 TITLE              → Game.go_to_title()   → title.tscn
```

Changing scene with `get_tree().change_scene_to_file()` **frees the whole current scene** and
everything in it (player, enemies, HUD, bullets). Only the autoloads survive, which is why score
and time live in `Game`, preferences in `Settings`, and the music keeps playing across scene
changes (its players belong to `Audio`).

## Core design principles

### 1. One scene = one idea = one script
Each `.tscn` has a root node with one script attached, and children that are only *parts* of it
(sprite, collision shape, hitbox, muzzle marker). You can open any scene on its own and understand
it.

### 2. Talk upward with signals, downward with calls
* A parent may call methods on its children directly (`$Sprite.play("idle")`).
* A child, or an unrelated node, tells the world something happened by **emitting a signal**.
  This project uses a global event bus (`Game`) so that, for example, the boss never needs to know
  the HUD exists.

### 3. Contracts over classes (duck typing)
Bullets don't check "is this an enemy?". They check "can this thing take damage?":

```gdscript
if body.has_method("take_damage"):
    body.take_damage(damage, global_position)
```

So the player, every mook and every boss can be hit by the same bullet, explosion and shockwave
code. A new destructible crate would only need a `take_damage` method.

### 4. Share behaviour with inheritance, vary it with overrides
`enemy_base.gd` handles health, gravity, flashing, contact damage, death and loot. Children
override one hook, `_ai(delta)`, plus optionally `_on_hurt()` / `_on_died()`. Bosses add a layer,
`boss_base.gd`, with activation, a state machine and phase 2, then override `_boss_ai(delta)`.

### 5. Data-driven where it helps
Tunable numbers are `@export` variables (editable in the Inspector). The level layout is arrays of
data in `build_level.gd`. Animation speeds are a table in `build_resources.gd`.

### 6. Game feel is cheap, so use it everywhere
Screen shake, hit-stop, hit flash, recoil, coyote time, jump buffering and variable jump height
each take a few lines but make a big difference. See
[gameplay/01-game-design.md](../gameplay/01-game-design.md).

## Scene ownership at runtime (level running)

```
root (Window)
├── Game                     ← autoload
└── Level1 (level.gd)        ← current_scene
    ├── Sky (CanvasLayer -20)    gradient + Stars
    ├── FarCity, MidCity         Parallax2D skylines
    ├── Buildings (z -5), Props (z -2)
    ├── Ground, Platforms        TileMapLayers
    ├── BoundLeft, BoundRight    invisible walls
    ├── Rain (CanvasLayer 5)
    ├── NightTint                CanvasModulate
    ├── Player
    │   └── Camera (game_camera.gd)
    ├── BossArena1..3
    ├── Enemies/…                19 mooks
    ├── Pickups/…                5 free pickups
    ├── HUD (CanvasLayer 10)
    └── (spawned at runtime: bullets, grenades, explosions, sparks, bosses, dropped pickups)
```

Spawned objects are added with `get_parent().add_child(...)`, which makes them **siblings** of
the node that spawned them, inside the level. If a bullet were added as a child of the player, it
would move with the player. As a sibling it flies on its own, and it is freed when the level is.
